# todoresolution

Microsoft To Do の「今日の予定」タスクに、緊急度・重要度・解像度を付けて優先順位を可視化するためのデスクトップGUIツール。

## できること

- 「Extract」ボタンで、Outlook デスクトップアプリの受信トレイから、件名「Microsoft To Do - 今日の予定」のダイジェストメールを読み込み、トップレベルのタスクのみを抽出する。
- 「Extract from File」ボタンで、ファイル選択ダイアログから指定した Markdown(`.md`)ファイルの内容からトップレベルのタスクを抽出する(Outlook が使えない環境向け。書式は Extract と同じ)。
  - いずれの抽出方法でも、既存のタスクがあれば新しく読み込んだタスクと突き合わせ、両方に存在するタスクは既存の緊急度・重要度・解像度を維持したまま、新規タスクの追加/消えたタスクの削除のみ行う(値は上書きされない)。
- 抽出したタスクをバブルチャート上に表示し、ドラッグ操作で緊急度・重要度・解像度を設定する。
  - 横軸: 重要度 / 縦軸: 緊急度(共に軸は逆進で、原点(左下)が(10, 10)、右下端が(0, 10)、左上端が(10, 0)) / バブルの大きさ: (10 - 解像度)
  - バブルの中心付近をドラッグ: 位置(重要度・緊急度)を移動
  - バブルの縁付近をドラッグ: サイズ(解像度)を変更
- 総合評価 = 重要度² × (緊急度 + 0.5 × (10 - 解像度)) を自動計算し、右側のテーブルに総合評価の降順でリアルタイム表示する。
- 「Reset」ボタンで、全タスクの重要度・緊急度を (5, 5) に一括リセットする(解像度は変更しない)。
- 「Save」ボタンで、任意のタイミングでタスクごとの緊急度・重要度・解像度を SQLite データベース(`todoresolution.db`)に保存する。
- 「Close」で閉じると、Save と同様に保存してからウィンドウを閉じる。次回起動時は自動的に読み込まれ、前回終了時の状態が復元される。

To Do 側への書き戻しは行わない。優先順位の確認結果は、ユーザーが手動で Microsoft To Do に反映する運用を想定している。

## セットアップ

前提: Windows + Outlook デスクトップアプリ(会社メールにサインイン済み)、Python 3.9 以降。

```
pip install -r requirements.txt
```

## 実行方法

```
python main.py
```

「Extract」ボタンを押すと、Outlook 受信トレイから対象メールを検索して読み込みます(複数件ある場合は最新のものを使用)。

## 注意事項

- 初回実行時、Outlook のセキュリティ機能により「プログラムがメール情報にアクセスしようとしています」という確認ダイアログが表示されることがあります。その場合は許可してください(組織のセキュリティポリシーによりダイアログの挙動は異なります)。
- 件名「Microsoft To Do - 今日の予定」のメールが受信トレイに存在しない場合は、エラーメッセージが表示されます。
- メール本文のうち、字下げされたサブタスクや Notes 等は取り込み対象外です。インデントのないトップレベルの `⬜` 項目のみを取り込みます。
- タスクの同一性はタスク名(文字列)で判定しています。同名タスクが複数存在する場合は区別できません。
- `todoresolution.db` はプロジェクト直下に作成されます。削除すると保存済みの値はリセットされます。

## EXE化(配布用実行ファイルの作成)

PyInstaller を使って単体の `.exe` を作成できる。

```
pip install pyinstaller
pyinstaller --noconfirm --windowed --onefile --name todoresolution main.py
```

- `--windowed`: コンソールウィンドウを表示しない(GUIアプリ用)
- `--onefile`: 単一の `.exe` にまとめる
- 生成物は `dist/todoresolution.exe`。`todoresolution.db` は `.exe` と同じフォルダに作成される(実行のたびに作られる一時フォルダではなく、`.exe` の場所を基準にしている)。
- Outlook 連携(`Extract`)を使う場合、実行するPCに Outlook デスクトップアプリ(クラシック版、`OUTLOOK.EXE`)が必要。新しい Outlook(`olk.exe`)は COM 自動化に対応していないため動作しない。「Extract from File」はこの制約を受けない。
- `build/` と `*.spec` は生成物なので配布時は `dist/todoresolution.exe` のみで良い。再ビルド時は `build/`・`dist/`・`*.spec` を削除してから実行すると安全。
